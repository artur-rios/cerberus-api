# Update profile content (UC12)

`PUT /api/profiles/{id}` replaces an owned active profile's opaque content. The route uses its canonical lowercase public GUID. Send a current identity bearer, one `X-Cerberus-Vault-Access` header and UTF-8 JSON containing only `expectedRevision`, `envelope` and `editedAt`. No query parameters, duplicate properties, numeric strings, unknown fields or compressed bodies are accepted.

The current account-wide session can update any own active profile; a valid selected session can update only its own selected profile. Invalid/expired/revoked policy contexts return403. Missing, foreign, trashed, erased or out-of-selection targets return the same404. Collection grants do not authorize another owner's profile. Missing identity/access returns401; identity provider and persistence outages fail closed503.

The envelope uses `cerberus-content-v1` and the current profile content epoch. It must contain canonical native binary metadata; the server never decrypts it. A changed envelope must replace both current key salt and nonce. Clients must implement durable cross-device fresh encryption accounting: comparison with the current envelope cannot establish historical uniqueness or decryptability. Exact unchanged envelope bytes remain valid for a metadata edit. Key epoch or wrapper/verifier changes require the separate native protection lifecycle; they are not body fields here.

`expectedRevision` is a positive exact integer through9007199254740991. Competing updates with the same expected revision permit one winner; stale edits and lost-response retries return409/revision_conflict, preserve the winner and require reload/retry. Revision/sequence exhaustion also returns409. Locks follow account/session/profile order. The final write rechecks access using PostgreSQL `statement_timestamp()` after all waits; transaction-start time cannot extend an expired session. Errors roll back the whole mutation.

Success200 contains only public `profileId`, new `revision`, monotonic `serverSequence` and stored `editedAt`. UTC client edit time is normalized down to microseconds before PostgreSQL binding, including dates before2000. Sequence gaps are valid. Sequence is the existing persisted synchronization marker; UC48 adds the change feed. The update preserves ownership, key wrappers, unlock mode/verifier, associations, account/protection state and session. Signed wrapper grant revision may precede content revision; native rotation validates that existing signed revision and binds its replacement to the new profile revision.

All responses are no-store. Corrupt stored native metadata returns503 without data or writes. Independent security/protocol and real-client approvals remain deferred for development only; the release manifest and strict main/tag release gate remain pending. Global OpenAPI required/nullability metadata correction is tracked before release.
