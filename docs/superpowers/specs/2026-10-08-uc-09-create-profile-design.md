# UC09 Create profile design

Source: issue10, UC09 main/AF01–05, FR-PR-01, common owned fields and Profile fields, BR03/04/10/12, owner permission matrix, native protocol review input. Independent protocol/client approval remains pending under explicit development deferral.

POST /api/profiles accepts exactly profileId, envelope, keyWrappers, editedAt, recordIds, folderIds, collectionIds. Client chooses a nonzero public ID before encryption. Revision starts1; duplicate/reserved public IDs conflict. EditedAt is UTC client time; database allocates a global monotonic safe-integer server sequence. Ownership derives exclusively from current authenticated identity and its active account. A current account-wide X-Cerberus-Vault-Access handle is mandatory. No query, plaintext name, passwords/private keys, unknown/duplicate fields or noncanonical encodings accepted. Return profileId/revision/serverSequence/editedAt, no internal ID or keys.

KeyWrappers contains unlockMode (Master or PerProfile), distinct scoped unlockVerifier, masterKeyWrapper and nullable passwordWrapper. The master wrapper uses existing native recipient-wrap format and pinned account recipient/author keys, owner account/resource profile/public ID/epoch, grantId=profileId and grantRevision=profile revision, recipientIdentityId=owner identity. This is an owner key wrapper, not a sharing permission. Native author signature verified before persistence; HPKE plaintext stays client-only. Master mode has no password wrapper; PerProfile has a native profile-protection password wrapper containing its independent profile root and scoped unlock private key. Client verifies bundle membership/private-public correspondence and encrypted required name. This permits ordinary profile creation without the recovery secret or rewriting opaque account recovery bundles. Account recovery restores the pinned recipient private key client-side; owner profile wrappers remain readable by that key. Cost if wrong: client root/private-key storage and recovery bundle integration need protocol/client review before release; no invented server decryption capability.

Only empty relationship sets resolve today because records/folders/collections do not yet exist; malformed/duplicate IDs400, any well-formed nonexistent relationship404. Extend the resolver in their first entity UCs. Profile IDs are checked against the permanent terminal reservation ledger and global profile index; no existence or content of another owner's entity is returned. Keep ProfileId session metadata without a new FK until selected-profile lifecycle UC15, preserving fail-closed stale-scope semantics; no selected handle may create profiles.

Account-first then session locks serialize creation with protection/lifecycle changes. Recheck statement-time access at INSERT, not transaction-start time; account policy/generation/closure/erasure and protection pins remain stable under account lock. Unique races409; dependency/serialization failures503; caller cancellation propagates. Transaction commits profile and sequence together (sequence gaps allowed); write failure rolls back profile. New envelope content epoch1 and master grant revision1.

UC39 integration: rotate-content requires exactly the account and all owned profiles including trash, no duplicates/foreign/extra/missing entries. Each profile replacement carries keyWrappers, expected profile revision, fresh ciphertext salt/nonce, epoch+1, retained scoped verifier/mode, new native owner wrapper binding next profile revision/epoch and current pins. PerProfile additionally replaces password wrapper with slot+1/fresh contexts. Preserve editedAt for maintenance rotation, advance server sequence/revision. Rewrap leaves profiles unchanged. All inventory validation precedes challenge consumption; all profile/account/protection writes rollback together. Selected-profile password changes remain UC15/its protection path when selected sessions exist; do not expose unusable profile management under account-only API.
