# UC10 permitted profile listing

Implement issue11 / FR-PR-02 and BR03/04/28. GET /api/profiles returns only the actor's active profiles in the current vault session's scope. Profile ownership never follows a collection grant: future shared collections expose their included content through the recipient's own profiles, never the owner's other profiles. No relationship entities or grants exist yet. Filter foreign ownership, trash, terminal erasures and selected-profile scope BEFORE ordering and pagination. An absent/closing/erased account returns404; invalid/revoked/expired/future/stale-policy/stale-generation or dangling/foreign/trashed selected session returns403. Missing authentication/access401, malformed visible inputs400, dependency/corrupt storage503. Reads never mutate.

Return items containing profileId, revision, serverSequence, editedAt, envelope and keyWrappers, plus nextCursor (null on last page). No totals, internal IDs, account contents or relationships. Encrypted envelopes allow clients to identify profiles without plaintext names. Revalidate stored opaque contracts; fail the whole page closed on corruption.

Use pageSize (default min(50, deployment MaxPageSize), positive decimal <= configured bound) and cursor, each exactly once; reject unknown query names, bodies and duplicate access headers. Cursor is a canonical base64url AES256-GCM encrypted tuple of actor, hashed access handle, size, after sequence and initial permitted maximum sequence. Derive a separate key by HMAC-SHA256 with a versioned purpose from the existing dedicated registration fingerprint secret; authenticate the same purpose as associated data. Same deployment key supports replicas. Changing it invalidates outstanding cursors (400, restart page1). No JWT key reuse or new persistent client secret. Strictly bounded cursor size. Recheck current account/session/visibility in ONE SQL snapshot on EVERY page. Sequence keyset + initial high watermark avoids duplicates and later inserts; concurrent edits may leave this ordinary listing and require refresh, not a synchronization snapshot guarantee. UC48 will define synchronization cursors separately.

Selected access remains a domain/persistence read restriction, tested using current session rows; UC15 owns proof issuance and cross-profile verifier isolation. Lists cannot mint access. MaxPageSize overflow is avoided by applying Take(size) with separate existence computation rather than size+1, or clamping lookahead safely. One normal final branch review; independent approvals remain deferred development-only.

AF mapping: AF01 query/header/body/cursor validation before store; AF02 ownership/scope/trash/erasure filters and empty lists; AF03 identity middleware plus store current account/session predicates; AF04 real missing-table/provider outages and corrupt-result guards.
