# UC15 profile access design
Intent: issue16 UC15 FRPR10/11 BR03/12, all AF01–06; current authenticated owner proves the selected profile key and receives a profile-restricted opaque handle and current native profile access context. Independent protocol/client approvals remain development-only deferred and release-gated.

Preferred design extends native VaultProof with its already-defined unlock-profile operation and profile scope; reuse VaultUnlockChallenge rows and VaultAccessSession.ProfileId. No new crypto or plaintext/private key fields. Alternative treating an account-wide handle as a profile proof would bypass separate profile unlocking; a client-asserted selection without proof is unacceptable.

Bootstrap POST /api/profiles/{id}/access/challenges with strict required expectedRevision/requestHash and a fresh identity bearer. Active current owned/nonterminal/nontrashed profile only; no existing handle needed to bootstrap profile-password unlocking. Return native challenge plus the opaque profile envelope/keyWrappers needed for local master decapsulation or per-profile password unwrapping. Owned encrypted bootstrap is like own account protection retrieval; no resource content, private material or unwrapped key is returned. Bind actor/account/profile public GUID, profile content epoch, current profile revision, generation:null, raw request SHA256 and random nonce/challenge for60 seconds. Existing account operations remain separate purposes/scopes.

POST /api/profiles/{id}/access strict required expectedRevision and original-body native proof headers. Account→profile locks serialize with writes/trash/rotation; resolve active owner/target before conflict/native checks. Verify current public key/native wrappers, policy/generation, operation/scope/body/revision/epoch/time, current identity and one-use challenge. Consume with final statement-time checks and insert only ProfileId-selected hashed32-byte opaque handle in same TX; current renewal policy determines finite or null expiry. Return accountId/profileId/profileRevision/vaultAccess/issuedAt/expiresAt plus current encrypted profile context and visible typed association IDs. Profile/account content and revisions are unchanged by unlocking. Use final current projection and validate response before commit; rollback failures return503 with proof unconsumed. Two simultaneous proof submissions yield one success. A lost committed response requires a new challenge/proof.

Key isolation: a scoped verifier must differ from account role pins and all other retained owned profile verifiers (including trash). Introduce an account-lock-protected shared validator; reject new duplicate keys on creation, fail closed when legacy ambiguous/corrupt keys are encountered at challenge/open. Current account-wide access still permits managing/trashing legacy profiles and creating replacements with fresh IDs/keys; never silently regenerate client secrets. Restore/future profile-protection changes must enforce the same invariant. No selected handle can be minted for ambiguous legacy keys. Signed challenge scope alone cannot repair a duplicated private key.

Failure map:400 malformed visible required body/routes/headers/native inputs;401 missing/failing identity or missing/invalid/replayed/expired proof;404 foreign/missing/trash/terminal/closing account or profile;409 changed visible profile revision/epoch or policy/generation;503 corrupt required native material, legacy verifier collision or unavailable dependencies. No data on failures, no-store on all responses. Empty/duplicate/unknown/case-mismatched/numeric-string/UTF8/BOM/compressed bodies and route/query misuse independently tested. Account/other-profile/recovery signatures cannot open this selection.

Verification: RED before every implementation; PostgreSQL native Master/PerProfile bootstrap/proof, cross-role/cross-profile/transplanted proof, strict expiry at consumption after account/profile waits, policy invalidation, replay/single winner, atomic rollback, content unchanged, selected read/list/mutate limited to original visible links, accountwide operations denied, trash revocation; actual Heimdall+HTTP tests; full unfiltered six families0fail/0skip >=90line, helpers/spec/OpenAPI/diff, one ordinary final review+one blocker correction pass, exacthead latest requiredCI/MERGEABLE/CLEAN normalmerge. Preserve primary files. Onebranch/issue/PR, archive own workspace after DoD thenUC16.

Concrete contracts: ProfileChallengeRequest(Guid Actor,Guid ProfileId,long ExpectedRevision,string RequestHash); ProfileAccessRequest(Guid Actor,Guid ProfileId,long ExpectedRevision,Guid ChallengeId,string Proof,byte[] RawBody); ProfileAccessInput(long ExpectedRevision) with required strict JSON; ProfileAccessMaterial(AccountId,ProfileId,Revision,Envelope,KeyWrappers) validates native structure and trusted actor/profile context; ProfileAccessContext(ProfileId,Revision,ServerSequence,EditedAt,Envelope,KeyWrappers,RecordIds,FolderIds,CollectionIds) validates metadata and typed sets. ProfileChallengeDetails(Challenge,Profile); ProfileAccessDetails(AccountId,Access,IssuedAt,ExpiresAt,Profile). IProfileAccessStore.ChallengeAsync(request,ct)/OpenAsync(request,ct). Commands IssueProfileAccessChallengeCommand and OpenProfileAccessCommand expose only required body fields; actor/profile/challenge/proof/raw context internal. Response challenge201: challenge/profile; open200: accountId/vaultAccess/issuedAt/expiresAt/profile (profile nine fields). Bootstrap profile five fields, opaque envelope/keyWrappers only; no association IDs before proof. Validate raw signed body's expectedRevision against trusted request at the store, in addition to its native hash.

AF coverage mapping: AF01 strict route/header/body/request types; AF02 current owned active profile/account before revision or native dependencies; AF03 provider identity/fresh challenge admission and proof authorization, no existing vault handle needed for bootstrap; AF04 expected profile revision, challenge policy/generation/epoch; AF05 native stored-material inconsistency or persistence failure503 without consumption/session; AF06 native bad/expired/replayed/wrong-scope proof401. FRPR10 current selected-session consumers already enforce scope; actual newly issued handles must exercise those consumers. FRPR11 Master and PerProfile both use scoped key from client-native bundle. Existing UC09 design's future profile-password-change path is not a flow in UC15; no extra password-change endpoint is added here. Rewrapping/master rotation remains existing UC39, and future profile-password changes must atomically rebind wrappers, enforce key isolation and revoke selected sessions.

Design self-check: cited FRPR10/11 and BR03/12 freshly loaded and present; no new services/dependencies/migrations, no protocol approval claim; every AF has a concrete path/test; scoped verifier rejection covers legacy ambiguity before any handle issuance. Existing explicit whole-batch authorization replaces repeated design/plan approvals, not verification.
