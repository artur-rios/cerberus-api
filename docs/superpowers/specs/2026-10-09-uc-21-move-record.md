## Alternatives and intent

Prefer a purpose-built transaction with current source/destination recursive snapshots, ordered own parent/collection/grant locks and a final guarded statement. Separate preflight followed by a write can move after authority changes. A generalized permission framework would widen this change without making its invariants clearer. The chosen approach pays targeted SQL maintenance and bounded related-collection contention.

## Scope and inherited relationships

Source uses the existing targeted current owner/selected/direct-folder/owned-collection and foreign native-grant scope, with complete active ancestry even for direct links. Native-visible foreign RO and RW both deny before destination probing, revision or target content inspection; validate every relevant foreign native contributor without foreign locks. Hidden404 precedes native corruption.

A nonnull destination must be an active, nonterminal owned folder with a complete active owned ancestry. Account-wide access can move to any such folder. Selected access requires the destination already be visible through a selected profile-folder ancestor or an owned collection-folder ancestor linked to that selected profile. A direct record link does not make its parent folder visible.

A selected handle may remove inherited visibility, including moving to null, but cannot expand existing content to new effective active owned profiles or collections. Compute all current effective owner profile/collection sets for the source and for the proposed parent, including unchanged direct record links; both resulting sets must be subsets of the original sets. This prevents a visible destination shared with another profile/collection from broadening existing content using only a restricted handle. Account-wide access may intentionally broaden. Apply the subset predicate again in the final statement. Unselected/hidden identifiers are never disclosed.

ProfileRecord, CollectionRecord, ProfileFolder, ProfileCollection and CollectionFolder rows remain unchanged. Get/list dynamically derive inherited membership from the new complete ancestry: old inherited routes disappear, new authorized routes appear, direct routes survive. No cached or materialized descendant membership is invented. Durable visibility-removal events belong to subsequent synchronization integration.

## Required native key envelopes

The native content protocol binds owner/kind/resourceID/epoch and explicitly states that moving preserves immutable identity. Folder parent is not authenticated content context. Recompute the required resulting active collection/grant set, validate every contributing outgoing native recipient envelope against its current collection envelope/epoch, grant/revision, owner author pins and recipient identity/pins, and preserve existing valid bytes. No resource identity, epoch, grant or key material is changed or generated by a parent move. Removed inherited-only routes need no new envelope and no longer authorize reads.

Validate current required native evidence after lock waits and require exact equality with the final statement's current evidence. Owner pins are protected by own-account serialization; foreign recipient pins are compared at statement time rather than locked. Relevant malformed or changed required wrappers fail closed without moving. Inactive/revoked/unrelated routes do not contribute. Native signature/shape validation does not prove opaque plaintext or actual client root availability: clients must validate authenticated decryption and trusted root availability, and any additional opaque client-supplied provisioning found necessary must be implemented before release. No server-generated usable key or fabricated client qualification is allowed.

## Transaction and lock order

Own actor account NO KEY UPDATE -> own session UPDATE -> selected owned profile NO KEY UPDATE if any -> union of current active direct/old-inherited/new-inherited owned collections in public-GUID order NO KEY UPDATE -> current resulting outgoing grant rows in public-GUID order SHARE -> distinct old/new immediate owned folders in public-GUID order NO KEY UPDATE -> target record NO KEY UPDATE. No ancestor, foreign account or foreign profile locks. Own account serializes legitimate owned create/association/rotation/lifecycle writers. Collection-before-content aligns with recipient edits; non-key parent/content locks permit FK KEY SHARE checks. No late acquisition of newly discovered earlier locks.

Reload source/destination/session/subset/native scope after each wait. Missing current authority and hidden state outrank conflict. New unheld collections/grants or changed source parent require409/reload. The final parameterized statement recomputes full source and destination ancestries, ownership/lifecycle/selection/subsets, exclusive database-time expiry, held sets and exact current validated native evidence, then updates FolderId/revision/sequence/stamp only if expected revision and original content/sequence/parent match. Zero rows are freshly classified403/404/503 before409. Statement-time snapshot is the linearization point; no commit-time expiry guarantee is implied.

Validate safe source revision/sequence, UTC microsecond EditedAt, active purge consistency and native content shape. This structural operation preserves valid opaque content; malformed visible content returns503 rather than being propagated to new scope. If the parent changes, validate and bump each distinct active old/new immediate folder's revision/sequence/stamp once, retaining its opaque content/clienttime/key metadata. Direct profile/collection links do not change, so those metadata and ancestor metadata do not bump. A no-op requires no parent revision capacity. Postwrite checks enforce exact next record/parent revisions and greater safe sequences. All target/parent writes commit together or roll back; exhausted counters409, corrupt/regressed results503, providerinternalcancellation503, callercancellation propagates.
