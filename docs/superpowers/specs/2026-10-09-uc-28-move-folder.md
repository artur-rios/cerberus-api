## Alternatives and selected architecture

An unguarded root parent UPDATE can authorize a stale destination or widen access to descendants; reject it. Reusing RecordMoveStore once per contained record invents parent changes and cannot move a folder atomically; reject it. Use a dedicated FolderMoveStore with current folder-only root admission, an explicit complete active subtree inventory, simulated current/result paths and per-member effective sets, stable ordered locks, current native result evidence and one guarded root parent UPDATE plus distinct old/new immediate parent metadata bumps. No schema, dependency, crypto algorithm, new usable key or server decryption.
