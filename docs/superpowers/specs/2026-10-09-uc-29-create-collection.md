## Intent and scope

Implement issue30, UC29 main flow and AF01..05, FR-CL01 and initial BR05/06 relationships. An active authenticated owner creates a private owned collection from opaque native ciphertext, with permitted initial profile, folder and record identifiers. Ownership comes only from current identity. The server never decrypts content or creates usable keys. Existing collection/member schema and complete native protection inventory are already present; no migration, dependency, grant, collection read/update/delete or membership replacement endpoint is added. Later UCs30..37 own those flows.

Dedicated strict command and dedicated guarded PostgreSQL store follow current folder/record creation conventions. Reusing the profile association resolver would require a broader interface and includes foreign collection attachment semantics unsuitable for owned member creation. Deferring initial members to UC34 would leave the UC29 submitted relationships incomplete. The dedicated flow is the chosen approach.

## Authority and permitted relationships

Current actor must map to an active nonterminal account and a current unrevoked own session, matching current positive policy/generation, IssuedAt<=database statement time, exclusive valid expiry when renewal enabled or explicit null expiry when disabled. A selection must remain an owned active nonterminal profile; never clear ProfileId to broaden access.

Account-wide permits empty links or multiple owned active profile links. Selected access requires exactly its current profile in profileIds; empty is403, other/multiple/foreign profile targets404. All requested folders and records must be owned by the actor's account, active/nonterminal and have complete active same-owner folder ancestry. Account-wide admits these owned members. Selection admits folders only through its PF ancestor routes or selected owned PC/CF routes; records additionally through direct PR or selected owned PC/CR routes. A record-only route never admits its containing folder. Direct child/member permission never reveals private ancestors or siblings. Relevant visible active cycles503; hidden/incomplete ancestors404 before corrupt opaque/native state probing. Unrelated cycles do not affect this create.

Foreign native RO/RW content cannot become a member of an actor-owned collection, even after actual successful native GET; return404 without changing either graph. No new grant or recipient access is created. Existing grants/keys/pins/protection and foreign/recipient metadata remain unchanged. Owned grouping does not decrypt or repair existing member ciphertext and does not require an unrelated native-grant proof. Unchanged owned authorization collections contribute only active typed membership routes: their unused opaque cipher or revision/sequence counters are not parsed or repaired, matching the existing creation boundary; there is no AF06/key-provisioning transition here. Selected initial membership cannot select an owned private root through the new collection: every member already needs current selected visibility before insertion.

## Five review priorities

- Selected creation must not attach an owned private member or foreign native recipient item, including record-only routes and mixed direct/inherited collection paths.
- Authority must remain current through every wait and the INSERT, with natural expiry or typed terminal/scope changes denying before uniqueness or stale metadata leaks.
- Collection-before-content order must serialize current owner and native recipient writers without foreign-account or upward-chain deadlocks; changed captured or unheld routes require reload.
- Collection, every initial typed link and every distinct directly affected structural counter must commit together or fully roll back after actual mutations; opaque bytes, times, prior trash and winner state remain exact.
- A newly created collection must enter complete native rotation inventory without widening selected sessions, inventing usable keys or claiming durable inherited visibility/client qualification.
