# UC-53: Expire retained deletions

Authority: UC-53 main flow and AF-01–05; FR-TR-06–08; BR-20,24,25,26. Internal worker only, with no human identity, public route, Heimdall mutation, schema migration or new dependency.

The existing `trash/{operationId}` and `account-purge/{accountId}` jobs carry their original exclusive 30-day deadlines. PostgreSQL statement time after row waits decides admission, lease validity and completion. Current typed terminal intents commit before filesystem I/O; the complete durable ledger set precedes atomic physical deletion. No database transaction spans ledger I/O. Retries preserve original deadlines and typed intent times. Active or independently retained resources and foreign native payloads survive.

Trash expiry locks owner, original job, original operation and owned resources in existing canonical order. It validates the original 720-hour operation and currently owned matching retained members. It admits and erases only that operation, with persisted claim fences at actual marker and physical statements. Missing already-erased operations safely complete; malformed or active members fail closed. A pre-deadline restore holding the same owner lock can win; expiry rechecks after waiting.

Account expiry takes the complete account/grant graph locks first, then the original job. It requires current ClosurePending state, the original valid 720-hour deadline at or before database time, and completed session/grant reductions. All current account targets receive fenced typed intent. The existing complete-set ledger and account erasure code performs deletion, retaining the executing job until completion. Other account-owned work and metadata are removed. Heimdall identity remains untouched. Cancellation winning before deadline completes the original job, clears its claim and prevents purge.

A bounded maintenance phase checks required database execution privileges before changes, repairs missing due original jobs after owner-lock/current-state rechecks, and removes expired abandoned sync streams with SKIP LOCKED. It never removes active-account sync-operation idempotency rows. Only missing jobs are repaired; an existing completed job is not reopened automatically. In valid flows completed trash jobs have no retained members and early account erasure already removed the account. Corrupt completed-job/native remnants remain fail-closed operational recovery cases.

The runner reports completed jobs, failed jobs, scheduled missing jobs and expired streams without identifiers or protected bytes. Database or ledger outages produce safe retry outcomes; cancellation propagates. No due objects or streams means zero writes. Worker rights are database least-privilege capabilities, not application bearer credentials. Restore traffic barriers still block workers until replay is complete.
